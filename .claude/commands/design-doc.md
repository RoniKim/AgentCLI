# 설계문서 생성 (AgentCLI 연동용)

당신은 소프트웨어 아키텍트입니다. 대상 프로젝트의 코드베이스를 분석하여 **AgentCLI가 참조할 설계문서**를 생성합니다.

## 대상 프로젝트 (필수)

대상 repo 경로: $ARGUMENTS

**중요**: 위 경로가 비어있거나 `$ARGUMENTS` 그대로이면, 반드시 아래 메시지를 출력하고 **즉시 중단**하세요:

```
오류: 대상 프로젝트 경로가 필요합니다.
사용법: /design-doc <프로젝트 경로>
예시: /design-doc D:\000.Work\MyProject
```

경로가 주어졌으면 해당 디렉토리가 존재하는지 확인 후 진행합니다.

## 작업 절차

### 1단계: 코드베이스 분석

대상 repo를 탐색하여 다음을 파악하세요:
- 프로젝트 유형 (웹앱, API, 라이브러리, 모바일 등)
- 사용 언어/프레임워크/패키지 매니저
- 디렉토리 구조 및 모듈 구성
- 진입점(entry point) 및 주요 흐름
- 빌드/테스트 방법 (build_cmd, test_cmd)
- 외부 의존성 및 인프라 (DB, API, 클라우드 등)
- 현재 코드의 품질 수준 및 기술 부채

### 2단계: 설계문서 작성

대상 repo의 `.doc/Docs/` 디렉토리에 아래 문서들을 생성합니다. 이미 존재하는 파일은 내용을 분석 후 보강/업데이트합니다.

#### A. `ARCHITECTURE.md` — 아키텍처 개요

```markdown
# Architecture

## 시스템 개요
(프로젝트가 무엇이고 어떤 문제를 해결하는지 1~3문장)

## 기술 스택
| 구분 | 기술 |
|------|------|
| 언어 | ... |
| 프레임워크 | ... |
| DB | ... |
| 빌드 | ... |
| 테스트 | ... |

## 디렉토리 구조
(주요 디렉토리와 역할을 트리로 표현)

## 핵심 모듈
| 모듈 | 역할 | 주요 클래스/함수 |
|------|------|----------------|
| ... | ... | ... |

## 데이터 흐름
(사용자 요청 → 처리 → 응답의 주요 경로를 설명)

## 외부 연동
(DB, API, 클라우드 서비스 등)
```

#### B. `CONVENTIONS.md` — 코딩 규약

```markdown
# Coding Conventions

## 네이밍
- 함수: ...
- 클래스: ...
- 상수: ...
- 파일: ...

## 패턴
(프로젝트에서 사용 중인 주요 패턴: DI, Repository, MVVM 등)

## 에러 핸들링
(프로젝트의 에러 처리 방식)

## 테스트 규약
(테스트 파일 위치, 네이밍, 프레임워크)

## 빌드/배포
- 빌드 명령: `...`
- 테스트 명령: `...`
- 배포 절차: ...
```

#### C. `CURRENT_STATE.md` — 현재 상태 평가

```markdown
# Current State Assessment

## 완성도
(전체적인 프로젝트 완성도 평가: 초기/중간/후반/유지보수)

## 동작하는 기능
- [ ] ...
- [ ] ...

## 알려진 이슈
- ...

## 기술 부채
- ...

## 개선 기회
- ...
```

### 3단계: AgentCLI Config 제안

분석 결과를 바탕으로 AgentCLI config에 반영할 권장 설정을 제안합니다:

```json
{
  "build_cmd": ["..."],
  "test_cmd": ["..."],
  "run_tests": true/false,
  "require_build": true/false,
  "goals_completion_level": "all",
  "iterations": N,
  "pm_refresh_every_cycles": N
}
```

### 4단계: DOCS_DIGEST.md 생성

대상 repo의 `.doc/DOCS_DIGEST.md`에 모든 설계문서의 목차/요약을 생성합니다. AgentCLI PM이 이 파일을 읽어 프로젝트 컨텍스트를 파악합니다.

```markdown
# Docs Digest

## ARCHITECTURE.md
- 시스템 개요: ...
- 주요 모듈: ...

## CONVENTIONS.md
- 네이밍 규칙: ...
- 빌드: ...

## CURRENT_STATE.md
- 완성도: ...
- 이슈 수: N개
```

## 출력 규칙

1. 대상 repo의 `.doc/` 디렉토리가 없으면 생성
2. 대상 repo의 `.doc/Docs/` 디렉토리가 없으면 생성
3. 기존 문서가 있으면 덮어쓰지 말고, 읽은 후 내용을 보강/업데이트
4. 모든 문서는 UTF-8 인코딩
5. 실제 코드를 읽고 분석한 결과만 작성 — 추측하지 않음
6. AgentCLI PM이 읽을 것이므로 명확하고 구조화된 마크다운 사용
